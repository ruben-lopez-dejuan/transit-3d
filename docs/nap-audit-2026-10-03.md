# Auditoría NAP V2 — 3 de octubre de 2026

La API oficial V2 usa `ApiKey` en cabecera. Un conjunto de datos contiene uno o
varios ficheros. El identificador estable de Transit 3D es la pareja
`datasetId:fileId`; `/fichero/{id}/descarga` devuelve un enlace S3 firmado durante
900 segundos y ese enlace no se persiste.

## Bilbao / Bizkaia

NAP descubre más cobertura que la selección principal actual: Bilbobus (`1259`,
GTFS `1460`), Bizkaibus (`1061`, `1262`), Euskotren (`1062`, `1263`), Metro Bilbao
(`1066`, `1267`), Funicular de Artxanda (`1063`, `1264`) y varios buses municipales.
También anuncia GTFS-RT, SIRI y NeTEx para varios operadores, pero esos recursos
figuran no válidos en el catálogo. No se sustituyen los adaptadores ricos de Bilbao:
conservan llegadas, GPS, túneles, geometría y fallbacks que el descriptor genérico
de NAP no aporta por sí solo.

No se cambió ninguna fuente de producción: NAP aporta descubrimiento reproducible
y una alternativa de adquisición, pero las fuentes directas actuales resultaron
iguales o mejores para vigencia, realtime o funcionalidad especializada.
